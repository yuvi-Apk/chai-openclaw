# .gitignore

**Purpose:** A list of files and folders that Git should **never track or commit**.

**Where it fits:** Git reads it automatically. It keeps the downloads from [package.json](package.json.md) (`node_modules`) and any secrets (`.env`) out of the repo. Pattern rules are explained in [concepts/gitignore.md](../concepts/gitignore.md).

---

### Dependencies and build output

```gitignore
node_modules
out
dist
*.tgz
```

**What it does:** It ignores installed packages, build folders, and packed tarballs.

**Why it's used in general:** These can be regenerated at any time, for example with `bun install`, so storing them only bloats the repo.

**Why it's used here:** `node_modules` holds commander, figlet, clack, and the rest. It is big and easy to recreate.

---

### Secrets: `.env` files

```gitignore
.env
.env.development.local
.env.test.local
.env.production.local
.env.local
```

**What it does:** It keeps environment-variable files out of Git.

**Why it's used in general:** `.env` files hold passwords and API keys. Committing them leaks them.

**Why it's used here:** This will matter a lot for Telegram mode. Your **Telegram bot token** should go in `.env` and never be committed.

---

### Logs, caches, and editor files

```gitignore
logs
_.log
coverage
*.lcov
.eslintcache
.cache
*.tsbuildinfo
.idea
.DS_Store
```

**What it does:** It ignores machine-specific or temporary junk: logs, test coverage, caches, IDE settings, and macOS folder files.

**Why it's used in general:** Each developer's machine makes these files. They aren't part of the project.

**Why it's used here:** It keeps commits clean, so only real source changes show up.

💡 **Tip:** `_.log` only matches a file literally named `_.log`. To ignore every log file, the usual pattern is `*.log`.

---

### 🧠 Key takeaways
- Ignore anything that can be regenerated, like `node_modules` and `dist`.
- **Always** ignore `.env`, because secrets live there.
- A clean `.gitignore` keeps commits focused on real code.
