# .prettierignore

**Purpose:** It tells Prettier which files and folders to **leave alone**.

**Where it fits:** It works with [.prettierrc](.prettierrc.md). The syntax is the same as [.gitignore](.gitignore.md) (see [concepts/gitignore.md](../concepts/gitignore.md)).

---

### Ignored paths

```gitignore
/.vscode
/node_modules
./dist

*.yml
*.yaml

*.env
.env
.env.*
```

**What it does:**
- `/.vscode`, `/node_modules`: skip editor settings and installed packages at the project root.
- `./dist`: meant to skip build output.
- `*.yml`, `*.yaml`: skip YAML config files.
- `*.env`, `.env`, `.env.*`: skip environment and secret files.

**Why it's used in general:** You don't want a formatter rewriting third-party code, generated files, or config files whose format matters.

**Why it's used here:** It keeps Prettier focused on the project's own source code, such as [index.ts](index.ts.md).

💡 **Tip:** In ignore files, a leading `/` means "from the project root", but `./` is not standard syntax. Writing `/dist` (or just `dist`) is the reliable way to match that folder.

---

### 🧠 Key takeaways
- `.prettierignore` uses the same pattern rules as `.gitignore`.
- Skip generated, third-party, and secret files.
- Use `/folder` to anchor a pattern to the project root.
