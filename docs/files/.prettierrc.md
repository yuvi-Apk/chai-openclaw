# .prettierrc

**Purpose:** The rulebook for **Prettier**, the tool that auto-formats your code so it always looks consistent.

**Where it fits:** Prettier is installed through [package.json](package.json.md). It reads this file when formatting files like [index.ts](index.ts.md). Files listed in [.prettierignore](.prettierignore.md) are skipped. See [concepts/prettier.md](../concepts/prettier.md).

---

### The formatting rules

```json
{
  "singleQuote": false,
  "bracketSpacing": true,
  "tabWidth": 2,
  "trailingComma": "es5",
  "semi": true
}
```

**What it does:**
- `singleQuote: false`: use double quotes, as in `"wakeup"`.
- `bracketSpacing: true`: put spaces inside braces, as in `{ Command }` rather than `{Command}`.
- `tabWidth: 2`: indent with 2 spaces.
- `trailingComma: "es5"`: add trailing commas where ES5 allows them, such as in arrays and objects.
- `semi: true`: always end statements with `;`.

**Why it's used in general:** Teams stop arguing about style because the tool decides. A shared config means everyone's code looks the same.

**Why it's used here:** It keeps `yuvi`'s code tidy as it grows. Once you run Prettier, `.command('wakeup')` becomes `.command("wakeup")`, the 4-space indents become 2 spaces, and semicolons get added.

💡 **Tip:** Run `bunx prettier --write .` to format the whole project at once.

---

### 🧠 Key takeaways
- `.prettierrc` sets the style; Prettier applies it automatically.
- This project uses double quotes, semicolons, and 2-space indents.
- Formatting changes how code looks, never what it does.
